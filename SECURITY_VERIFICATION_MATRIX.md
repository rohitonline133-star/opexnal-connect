# Opexnal Security Verification Matrix

| AREA | STATUS | EVIDENCE | LIMITATION |
| :--- | :--- | :--- | :--- |
| **Authentication** | PASS | Supabase Auth integrated with email/password, session persistence, PKCE token exchange, and password strength validation in `src/routes/auth.tsx` & `src/integrations/supabase/auth-middleware.ts`. | Social OAuth providers (Google/GitHub/Apple) require external client IDs and redirect URI binding in provider console. |
| **Password Hashing** | PASS | Server-side cryptographic hashing via Supabase Auth (Argon2id/bcrypt standard). Client-side zero-knowledge k-Anonymity breach verification in `src/server/threat-intelligence.ts`. | Client-side never accesses raw password database hashes; relies on Supabase Auth cryptographic engine. |
| **Sessions** | PASS | Secure token-based sessions with automatic refresh token rotation (`autoRefreshToken: true`), local storage persistence, and logout-everywhere capability via `supabase.auth.signOut()`. | Long-lived sessions require periodic reauthentication for high-risk actions. |
| **MFA/2FA** | PASS | Supabase TOTP MFA factor enrollment and verification APIs supported in `src/routes/_authenticated/settings.security.tsx` with adaptive step-up risk challenges (`REQUIRE_MFA`). | SMS-based MFA requires downstream Twilio/MessageBird provider configuration. |
| **Authorization/IDOR** | PASS | Server isolation ensures user context is derived strictly from verified auth token (`session.user.id`), not untrusted client payload IDs (`tests/settings-and-security.test.ts`). | Requires consistent enforcement across all custom RPC functions and table policies. |
| **PostgreSQL/RLS** | PASS | Row Level Security (RLS) enabled on core tables (`posts`, `profiles`, `likes`, `comments`, `follows`, `messages`, `conversations`). Client requests execute through RLS scoped to `auth.uid()`. | Database superuser/service-role bypasses RLS if connection strings are leaked. |
| **API Validation** | PASS | Strict schema parsing via Zod across auth, media, settings, and AI endpoints; rejection of invalid payloads and type coercion. | Complex nested multipart form data requires secondary stream inspection. |
| **Rate Limiting** | PASS | Multi-tier sliding-window rate limiter implemented in `src/server/edge-security.ts` (`checkEdgeTierRateLimit`): Auth (15 req/m), AI (20 req/m), Security (30 req/m), Static (300 req/m). | Origin in-memory sliding window resets on origin instance restarts unless backed by Redis. Provider edge rate limiting requires Cloudflare WAF deployment. |
| **CSRF** | PASS | Anti-CSRF token verification and SameSite cookie policies configured. Non-GET mutations require explicit Bearer tokens or verified custom origin headers. | Classic form POST without custom headers must be blocked or isolated to CORS preflight. |
| **CORS** | PASS | Strict hostname and origin validation in `src/server/gemini-handler.ts` (`isAllowedOrigin`) rejecting unauthorized third-party cross-origin requests. Wildcard `*` prohibited. | Subdomains must be explicitly allowlisted in production environment config. |
| **Security Headers** | PASS | Enforced in `src/server/edge-security.ts` (`applyEdgeSecurityHeaders`): CSP, HSTS (`max-age=31536000; includeSubDomains; preload`), `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Permissions-Policy`. | Strict CSP disallows unapproved external CDN script tags unless nonced or hashed. |
| **Storage** | PASS | Supabase Storage bucket policies enforce user-scoped directory isolation (`/avatars`, `/posts`, `/audio`). Path traversal sanitized via `sanitizeStoragePathSegment`. | Bucket public read flags must be kept disabled for private user media. |
| **Media Validation** | PASS | Multi-attribute media validator in `src/lib/security.ts` (`validateMediaFile`) verifying MIME whitelist, maximum payload size (15 MB), and extension matching. | Deep binary polyglot and steganography analysis requires external ClamAV/virus sandbox pipeline. |
| **Realtime** | PASS | Supabase Realtime channel subscriptions with channel authorization (`channel.subscribe()`). | Realtime connection quotas and WebSocket broadcast message rate limits depend on Supabase infrastructure tier. |
| **AI Security** | PASS | Multi-stage prompt defense in `src/server/ai-security.ts` (`inspectPromptSecurity`): heuristic injection detection, DAN jailbreak rejection, system prompt forgery defense, and secret token redaction. | Advanced zero-day adversarial jailbreaks require continuous red-teaming and classifier retraining. |
| **Risk Engine** | PASS | Centralized behavioral scoring in `src/lib/risk-engine.ts` (`calculateCentralizedRiskScore`): multi-signal evaluation (0-100), progressive delay backoff with jitter (`calculateProgressiveDelayMs`). | Real-time sliding window counters are memory-resident per origin node. |
| **REAL ML** | NOT VERIFIED | ML architecture implemented in `src/server/ml-security-pipeline.ts` with feature extraction, labeled event schema, drift monitoring, false-positive tracking, and graduated actions (ALLOW/CHALLENGE/RATE_LIMIT/TEMPORARY_LOCK). Marked NOT VERIFIED due to absence of trained offline model weights in repository; safe fallback to deterministic rules is active. | Requires offline dataset collection, training (GBM/Random Forest), model weight serialization, and evaluation metrics before upgrading status to PASS. |
| **Impossible Travel** | PASS | Haversine distance and physical velocity calculation in `src/lib/risk-engine.ts` (`evaluateImpossibleTravel`), flagging speeds exceeding 850 km/h over non-metro distances (>50 km). | Requires reliable geographic telemetry (latitude/longitude) from client or IP geolocation header (e.g. `cf-ipcountry`, `cf-iplatitude`). |
| **Bot** | PASS | Browser signature entropy verification, headless/automation scanner detection (sqlmap, nikto, puppeteer, playwright, curl), and suspicious header inspection in `evaluateDeviceBotSignals`. | Sophisticated human-emulating browser farms require Cloudflare Turnstile or managed CAPTCHA challenges. |
| **Edge DDoS Protection** | PROVIDER CONFIGURATION REQUIRED | Infrastructure-as-code defined in `terraform/edge-security.tf` (Cloudflare Anycast DNS proxy, HTTP DDoS managed ruleset override, strict TLS 1.3, rate limits). | Upstream Anycast L3/4 volumetric DDoS mitigation cannot be executed in application code; requires active Cloudflare / Cloud Armor deployment. |
| **Origin Protection** | PASS | Origin secret inspection implemented in `src/server/edge-security.ts` (`verifyOriginSecret`) using constant-time equality (`safeTimingEqual`) and strict mode fail-closed behavior. | Production deployment requires setting `ORIGIN_VERIFY_TOKEN` and configuring Cloudflare header injection (`X-Origin-Verify`). |
| **Cyber Threat Intelligence (CTI)** | PASS | Static baseline for Tor exit nodes, active botnets, and high-risk ASNs in `src/server/threat-intelligence.ts`. Comprehensive SSRF filtering for Cloud Metadata (IMDSv1/v2) and RFC1918 private ranges. Live external CTI feeds marked NOT VERIFIED. | Automated live CTI sync requires external API keys for commercial feeds (AbuseIPDB, AlienVault OTX). |
